# 高还原作业手册：从截图到 Elementor（实战版）

这个手册用于处理“直接捕获失真很大”的区块。
目标：最大化还原样式、排版、图片和 JS 效果。

## 1. 什么时候必须走这套流程

满足任意一条就建议使用：

- 粘贴后图片区块丢失明显。
- 排版错位严重（容器塌陷、重叠、比例异常）。
- 关键交互失效（轮播/Tab/Accordion/点击切换）。
- Elementor 中变成 HTML Widget 且可编辑性不足。

## 2. 输入物清单（缺一不可）

1. 原页面截图（至少桌面端 1 张）。
2. 关键交互状态截图（例如 Tab A/Tab B、轮播前/后）。
3. 当前捕获得到的 HTML/CSS（哪怕不完整也要给）。
4. 必须保留的行为清单（例如“hover 要有阴影，轮播要能切换”）。

## 3. 交给 AI 复刻的标准提示词（可直接改）

```text
请你根据我提供的截图和代码，输出一个“可直接运行的自包含前端区块”：
1) 输出完整 HTML + CSS + JS。
2) 不依赖外部站点私有插件运行时。
3) 视觉、排版、间距、层级尽量和截图一致。
4) 必须还原交互：<在这里写你的交互要求>。
5) 代码需语义清晰，类名可维护。
6) 所有图片请用可替换 URL，并在代码顶部集中声明。
7) 输出后附“可调参数清单”（字号、间距、主色、圆角、动画时长）。
```

## 4. AI 输出验收标准（不满足就打回）

1. 打开后视觉是否接近原图（主观误差 <= 10%）。
2. 交互是否可点可切换。
3. 是否有明显外部依赖（若有必须去掉）。
4. 是否包含可调参数清单。

## 5. 转 Elementor 的落地流程

1. 将 AI 复刻代码输入你的转换链路（插件或 Skill）。
2. 粘贴到 Elementor。
3. 只做局部修正：间距、字号、断点。
4. 不要在 Elementor 里重写大段结构（那会导致下一次不可复用）。

## 6. 你的 Skills 应该怎么用

建议顺序：

1. `$brainstorming`
- 明确“必须还原项”和“可接受妥协项”。

2. `$gemini-to-wordpress-acf-plugin`
- 将复刻后的 HTML/CSS/JS 生成 Elementor JSON 或 hybrid/plugin 结果。

3. `$systematic-debugging`
- 对图片丢失、布局错位、交互失效做结构化排查。

4. `$verification-before-completion`
- 交付前按清单验证，不靠主观感觉。

## 7. 失败时快速回退策略

- 方案 A：保留 HTML Widget（先保真上线，再逐步组件化）。
- 方案 B：将复杂交互区拆成两个部分：
  - 静态视觉部分走 Elementor 原生组件。
  - 交互核心部分保留 HTML/JS。

## 8. 最终交付包建议

交付时保留以下文件，方便后续维护：

1. 原图截图（含交互状态截图）。
2. AI 复刻源码（HTML/CSS/JS）。
3. 最终 Elementor JSON。
4. 调参说明（字号、色值、断点、动画时长）。
5. 已知差异说明（如果有）。
