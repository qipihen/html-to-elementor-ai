# Elementor Capture Hub 实操手册（中文）

本手册不是功能介绍，而是可直接照做的操作流程。
目标：尽可能还原你捕获到的区块在 Elementor 里的样式、排版、图片和交互。

## 1. 你先记住这件事

- `Capture` 页签是主流程。
- `AI Enhance` 是可选增强，不是必选步骤。
- 复杂区块（轮播/Tab/第三方插件区块）有概率降级为 `HTML Widget`，这是当前技术边界，不是你操作错了。

## 2. 3 分钟快速流程（90% 场景）

1. 打开目标页面，先把目标区块完整滚动到可见区域。
2. 触发一次区块交互：切一次 Tab、点一次轮播 next、触发一次 hover。
3. 打开右下角 `Capture Hub`。
4. 在 `Capture` 页签点击 `Start Capture`。
5. 在页面点目标区块。
6. 切到 Elementor 编辑器，直接 `Ctrl+V`。
7. 如果效果差异大，走第 4 章“高还原流程”。

## 3. 标准捕获流程（细化版）

### 3.1 捕获前准备

1. 关闭页面缩放（浏览器缩放建议 100%）。
2. 等待页面加载完成（图片、字体加载后再捕获）。
3. 如果有懒加载图片：把区块上下滚动一遍，让图片真的加载出来。
4. 如果有状态切换（Tab/Accordion/Slider）：至少切换一次，让对应 DOM 和样式进入已渲染状态。

### 3.2 捕获与粘贴

1. `Capture Hub` -> `Capture` -> `Start Capture`。
2. 鼠标选中尽量“完整的一块容器”，不要跨多个大区块。
3. 捕获后立即去 Elementor `Ctrl+V`。
4. 粘贴后先看四个点：
- 图片是否都在
- 主体布局是否没塌
- 字体/间距是否近似
- 关键交互是否可点

### 3.3 何时继续微调、何时切换流程

- 轻微偏差（间距、字号、圆角）：直接 Elementor 里微调。
- 大偏差（图片丢失、结构错位、交互失效）：不要硬调，直接走第 4 章。

## 4. 高还原流程（复杂区块必用）

适用信号：
- 类名出现 `gspb/greenshift/swiper/slick/owl/splide`。
- 区块高度依赖 JS 状态。
- 粘贴后 Elementor 显示为 `Edit HTML` 且差异很大。

### 4.1 采集“复刻输入包”

1. 目标区块截图（PC 视图，必要时再加移动端截图）。
2. 关键交互录屏或连拍（例如轮播切换前后）。
3. 区块 HTML（捕获结果/页面源码片段）。
4. 关键样式（computed style 或核心 CSS 片段）。

### 4.2 让 AI 先做“自包含复刻”

把上面输入包给 AI，明确要求：
- 输出完整 `HTML + CSS + JS`。
- 不依赖站点私有插件运行时。
- 图片 URL 可替换但结构和视觉要一致。
- 交互必须可运行（Tab/Slider/Hover/动画）。

### 4.3 再转 Elementor

1. 把 AI 复刻后的完整代码再转 Elementor（通过你当前插件流程或 Skill 工作流）。
2. 粘贴进 Elementor。
3. 仅做最后 5%-10% 的视觉校准。

## 5. AI Enhance 页签怎么正确用

- 有捕获：可用捕获数据 + Base JSON 做增强。
- 无捕获：现在支持 `JSON-only`，只粘 Base JSON 也能跑。
- 目的：优化已有 JSON，不负责自动补全所有丢失资源。

建议：
- 如果区块本身已经严重失真，先做第 4 章复刻，再做 AI Enhance。

## 6. 为什么会变成 HTML Widget

这是当前策略的“保真优先降级”：
- 当区块过于复杂，直接强拆成 Elementor 原生组件会更容易错位。
- 系统会保留为 HTML 区块，先保证视觉和交互尽量不丢。

你可以把它理解为：
- `原生 Elementor 可编辑性` 和 `复杂交互还原度` 常常不能同时拉满。

## 7. 常见问题与处理

### Q1. 提示 `Load a capture first`

- 在 `Capture/Export` 页签，这条提示是正常的（这两页依赖捕获数据）。
- 在 `AI Enhance` 页签，如果你已经粘 Base JSON，现在可直接运行；若仍提示，请先 `Reload` 扩展。

### Q2. 图片大量丢失

按顺序检查：
1. 捕获前是否让懒加载图片进入可见。
2. 图片是否防盗链或短时签名 URL。
3. 背景图是否在伪元素里（`::before/::after`）。
4. 资源是否来自跨域且不可直接访问。

### Q3. 排版完全乱

- 通常是第三方栅格系统依赖缺失（例如 Greenshift/Gutenberg 运行时）。
- 走第 4 章高还原流程，不要在错误结构上硬调。

### Q4. 交互动效没了

- 先确认捕获前是否触发过该交互。
- 如果仍失效，说明依赖 JS 运行时不可直接迁移，建议 AI 自包含复刻后再转。

## 8. 推荐作业节奏（高成功率）

1. 每次只处理 1 个区块。
2. 先做“首屏关键区块”，别先做零碎模块。
3. 每完成一个区块就立即在 Elementor 验收，不要批量堆积后统一排错。
4. 保留原页面截图和最终页面截图，方便对比回归。

## 9. 验收清单（交付前）

1. 视觉：字号、行高、间距、圆角、阴影、颜色一致。
2. 结构：容器宽度和对齐方式正确。
3. 资源：图片都可见、清晰度正常。
4. 交互：按钮、切换、轮播、hover、动画可用。
5. 响应式：至少检查桌面和移动端各一次。

## 10. 安全与隐私

- 不要把客户私有页面截图、导出 JSON、API Key 上传到公开仓库。
- 建议使用私有仓库管理中间产物。
- 对外协作前先清理业务敏感字段与私链 URL。

## 11. 与 Skills 配合（建议）

当你要“最大化还原”复杂区块时，推荐顺序：

1. `$brainstorming`：先定义必须还原项（样式/排版/交互）。
2. `$gemini-to-wordpress-acf-plugin`：把复刻代码转成 Elementor JSON 或 hybrid/plugin 结果。
3. `$systematic-debugging`：排查图片丢失、布局错位、交互失效。
4. `$verification-before-completion`：交付前按清单验收，避免漏项。
